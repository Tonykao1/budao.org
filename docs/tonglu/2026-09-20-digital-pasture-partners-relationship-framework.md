# 数字牧场 Phase 2｜同路伙伴关系框架 v0.1

日期：2026-09-20  
状态：交互原型基线

## 1. 核心隐喻

- 一颗葡萄 = 一个 Person。
- 一串葡萄 = 一个 Relationship Group / 一组真实关系。
- 一根枝条 = 一段可追溯的真实关系路径。
- 一整棵葡萄树 = 当前用户能够看见的关系世界。
- 默认不显示姓名；先看关系，再看身份。
- 葡萄不拟人化，不戴眼镜，不使用头像脸、等级徽章或粉丝数。

## 2. 产品目标

保留传统社交网络最有价值的能力：
- 认出熟人；
- 发现共同关系；
- 通过弱连接发现新的人；
- 看见群组与共同经历；
- 从关系进入消息、信箱、共同活动。

同时拒绝传统社交网络的默认表达：
- 不做好友列表；
- 不做 follower / like 竞争；
- 不做无限 feed；
- 不做“共同好友 17 人”式抽象计数；
- 不以资料页为关系入口。

《同路伙伴》的核心不是“你认识谁”，而是：

> 你如何沿着真实关系走到另一个人那里。

## 3. 四层数据模型

### Person
唯一的人，不因加入多个关系组而复制身份。

建议字段：
- person_id: UUID
- public_id: 可选的人类可读 ID
- display_name
- visibility_policy
- created_at
- last_active_at

### RelationshipGroup
一串葡萄代表一个关系上下文。

建议字段：
- group_id
- group_name
- group_type
- palette_key
- created_at
- archived_at
- visibility_policy

group_type 示例：
- family
- church
- budao
- workshop
- small_group
- event
- project

### Membership
Person 与 RelationshipGroup 的多对多连接。

建议字段：
- membership_id
- person_id
- group_id
- joined_at
- left_at
- relation_context
- last_interaction_at
- shared_event_count

同一个 Person 可以同时属于多个 Group；前端可在多个葡萄串中出现，但点击后始终指向同一个 person_id。

### RelationshipEdge / Path
用于“藤路”。

建议字段：
- from_person_id
- to_person_id
- source_group_id
- source_event_id (optional)
- edge_type
- visibility_policy
- established_at

一条边必须有真实来源语境，不能只是“系统认为你们可能认识”。

## 4. 三层交互

### Level 1｜树冠
默认状态。
- 只显示用户可见的一度关系串；
- 不显示名字；
- 不显示人数统计；
- 不显示粉丝数或好友数；
- 只通过颜色簇、枝条位置与葡萄串展示关系结构。

### Level 2｜葡萄串
点击一串：
- 该串前移 / 高亮；
- 其它枝叶退后；
- 此时才显示关系组名称；
- 可查看“这串为什么存在”的共同语境。

### Level 3｜单颗葡萄
点击一颗：
- 显示人物姓名；
- 最近共同经历；
- 最近互动；
- 可进入：信箱 / 风闻 / 共同走过 / 步道卡关联。

不做完整个人主页。

## 5. 藤路

“藤路”是关系路径模式。

输入/选择一位当前非一度关系的人后，系统展示一条真实可验证的关系路径：

Tony → A → B → C → 对方

表现方式：
- 枝条逐段亮起；
- 每经过一个人，亮起一颗葡萄；
- 不显示复杂 network graph；
- 不把所有二度、三度节点一次性铺开。

产品语言：
- “与你相隔 3 步”
- “从这根枝条出去，三步以后有人在东京”

不使用：
- “3rd-degree connection”
- “共同好友 26 人”

## 6. 七步之内

七步是产品探索上限，不宣称为社会科学定律。

规则：
- 单次藤路探索最多经过 7 个 Person 节点；
- 找不到路径时只说“这条藤还没有接上”，不推断关系不存在；
- 不展示全网图谱；
- 不允许通过七步机制批量爬取陌生用户。

目的：
- 保持探索的诗意和有限性；
- 避免变成 LinkedIn 式关系挖掘工具；
- 给“走向远方”一个明确交互边界。

## 7. 隐私原则

关系图谱天然敏感，因此默认最小暴露。

- 一度关系：按双方关系与可见设置展示；
- 二度及以上：优先展示“路径存在”，而不是完整个人资料；
- 路径中间节点必须允许隐藏姓名，只显示匿名葡萄；
- 群组成员列表不因某一成员可见而自动全部可见；
- 不允许从一个公开葡萄反推出完整群组成员；
- 搜索与藤路使用相同权限边界。

## 8. 视觉语义

颜色：
- 表达关系簇，不表达人的价值或亲疏等级。

大小：
- 主要用于自然构图；
- 不表达社会地位；
- 第一版不编码“重要程度”。

亮度：
- 可轻微表达最近有互动；
- 不表达“关系好坏”。

生长：
- 新关系：出现小葡萄 / 新芽；
- 新共同经历：枝条出现一片新叶；
- 久未互动：安静、降低动势，不枯萎；
- 关系结束：可转入远枝 / 历史枝，不用枯死惩罚。

## 9. 与其它模块连接

- 信箱：从单颗葡萄进入写信 / 读信。
- 风闻有你：某条风闻可指向相关 Person / Group。
- 步道卡：共同参加事件形成 shared_event。
- 我的牧草：第一版不强绑定，未来再设计共同读经或同行痕迹。

## 10. 第一版原型范围

做：
- 巨大像素葡萄树；
- 5 组关系串；
- 每颗葡萄一个 Person；
- 默认无姓名；
- 点击葡萄串显示组名；
- 点击单颗葡萄显示人物小信息层；
- 一条“藤路”演示；
- 七步之内的路径计数；
- 枝叶轻微自然动态。

暂不做：
- 正式关系写入；
- 邀请 / 加好友；
- 搜索陌生用户；
- 权限管理 UI；
- 正式消息跳转；
- 全网路径计算服务；
- 推荐算法。

## 11. 验收句

> 默认看到的是一棵关系之树；点击一串才知道“我们为什么在一起”；点击一颗才知道“你是谁”；沿着枝条，有限地走向更远的人。
