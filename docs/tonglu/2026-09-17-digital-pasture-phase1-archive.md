# 同路 · 数字牧场｜阶段1归档

日期：2026-09-17
状态：阶段1封存，进入阶段2
开发分支：`feature/tonglu-pixel-pasture-v1`

---

## 1. 产品定义

**同路 = 步道用户的数字牧场。**

“网页版游戏 + 电子宠物”只作为内部交互隐喻，不作为对外定义。

用户不是“拥有一只羊”，而是**以一只羊的形象进入牧场**。数字羊不是头像、皮肤、宠物或装饰，而是用户在数字牧场中的存在本体。

核心句：

> 一只羊在数字牧场里，如何生活、如何被看见、如何与别的羊同行、如何被喂养、如何给予。

判断标准：

> 它像不像“步道用户的数字牧场”？不像，就删；像，才继续做。

---

## 2. 世界观与视觉宪法

整体方向：**像素童话牧场**。

固定要求：

- 高度像素化，但去掉粗糙感。
- 治愈、安静、童真、抽象、可爱。
- 表层不显宗教性，不出现十字架、光柱、鸽子、火焰、圣经 App、讲道海报或宗教口号。
- 牧场没有围栏、硬边界或“被装进页面”的感觉。
- 从一开始就考虑未来 IP 与周边延展。

核心空间句：

> 不是一个装着羊的页面，而是一片暂时被屏幕看见的牧场。

像素感原则：

> 像素感保留，粗糙感去掉；美感保留，Flash 感去掉。

第一眼必须成立的感觉：

- 我进入了一片牧场。
- 我就是一只羊。
- 我看到了其他羊。
- 这里正在发生一些事情。

---

## 3. 步道羊视觉圣经 v1

数字羊定位：**用户在数字牧场中的存在本体。**

性格基线：

- 懵懂
- 可爱
- 呆傻
- 天真

固定气质：

> 它不是“厉害的羊”，而是“让人想陪伴的羊”。

比例：

- 大身体
- 小脑袋
- 短腿
- 身体约 65–75%
- 头部约 15–20%
- 腿约 10–15%

差异来源：

- 羊毛颜色
- 小角
- 耳朵
- 眼睛
- 步态

不采用炫耀型装扮、等级皮肤、皇冠、稀有坐骑等系统。

固定原则：

> 步道羊的差异应该来自生命气质，不应该来自炫耀型装扮。

身份差异只通过责任痕迹呈现，例如小铃铛、布结、杖影、较稳定站姿等。

固定句：

> 身份不是权力升级，而是责任痕迹。

动画目标是“活着”，不是“表演”。

情绪通过姿态、节奏、距离表达，不通过 emoji。

IP 公式：

> 步道羊 = 像素童话感 × 懵懂呆萌 × 极简抽象 × 安静生命感 × 可长期IP化

## 4. 信息架构：牧场总览态 / 自我聚焦态

### A. 牧场总览态 / Social Pasture Layer

含义：**我在共同体里。**

用途：

- 看世界
- 看其他羊
- 看关系正在发生
- 看少量社会性信号

原则：

> 牧场负责看见关系正在发生。

总览中不使用“我的羊”等表达。

自己的羊存在于群体中，但不过度居中、标记或特权化。

### B. 自我聚焦态 / Self Life Layer

点击自己的羊进入。

含义：**这就是我当前的生命状态。**

不是 profile，不是 dashboard，不是个人中心。

标题格式：

> 同行 N 天的 Username

固定五个世界内对象：

1. 风铃：牧养 / 有人来关心
2. 灵粮：读经与喂养
3. 呼唤声波：需要
4. 浅黄色不规则手帕：给予
5. 出发木板：个体化活动 / 出发信息

固定原则：

> 近景负责处理与我有关的事情。

> 总览态负责世界成立；聚焦态负责身份成立。

用户习惯目标：

> 进入同路 → 看一眼牧场发生了什么 → 点自己 → 看自己的状态 → 再回到牧场回应别人。

## 5. 五种社会 / 内容维度

### 5.1 活动信息

不是第二个活动列表，也不是公开发布频道。

定义：

> 这只羊收到一次与自己有关的出发信息 / 出发邀请 / 召唤 / 提醒。

公开活动仍由主站承载；同路只做个体化出发。

在自我近景中使用小木板，不在公共牧场放置公共活动牌。

### 5.2 牧养信息

定义：

> 有人来关心这只羊。

视觉语言：风铃。

风铃不是消息徽标，而是“有人来过”的痕迹。

### 5.3 灵粮

正式名称：**灵粮**。

定义：

> 这只羊正在吃草、走路、成长。

视觉语言：略亮、轻微闪烁的特殊牧草。

交互：点击直接打开媒体，不经过中间卡片。

一次性规则：

> 一份灵粮，一次开启。打开以后即消失，不进入历史记录，不提供再次查看。

### 5.4 步道需求

定义：

> 这只羊发出需要帮助的信号。

视觉语言：柔和声波，不用警报、红点、聊天气泡或上传图标。

默认：三道柔和蓝色呼唤声波。

需求类别可以使用低饱和色区分，例如实务、陪伴、祷告安慰、路线装备、生活关怀等。

### 5.5 给予 / 易彼益

第一语言不是交换，而是**给予**。

固定句：

> 这只羊愿意把什么给予出去。

> 易彼益在数字牧场里的第一语言不是交换，而是给予。

自我近景符号：浅黄色、不规则手帕。

避免礼盒、电商、价格牌、二手交易 UI。

## 6. 世界对象语法

固定原则：

> 功能不是图标；功能变成世界里的自然物与自然事件。

> 能成为世界里的东西，就绝不做成按钮。

对象映射：

- 草：绿色呼吸面
- 树：关系节点 / 安静朋友
- 风铃：牧养痕迹
- 灵粮：特殊牧草
- 需求：羊的呼唤声波
- 给予：手帕 / 放在草地上的物件
- 出发：木板与小路

已通过交互原则：

> 图标—文字—点击区域一一对应。

> 一物一签，悬停显明。

## 9. 注册、数字羊、步道卡：身份体系底层规则

这是阶段1末尾确定并正式锁定的身份架构。

### 9.1 核心关系

> 注册 = 取得数字身份。

> 数字羊 = 这个身份在数字牧场中的身体。

> 步道卡 = 现实世界对这个身份的确认。

> 步道卡激活码验证成功 = 完成正式激活。

### 9.2 固定顺序

**注册 → 生成步道 ID → 生成数字羊 → 获得步道卡 → 输入卡上激活码 → 卡、步道 ID、数字羊一一绑定 → 激活完成。**

### 9.3 固定身份原则

> 一人一身份，一身份一只数字羊，一只数字羊绑定一张当前有效步道卡。

注册生成数字羊；取得步道卡以后，必须通过卡上的唯一激活码与该数字羊身份一一对应，才完成正式激活。

### 9.4 永久核心与可替换凭证

永久身份核心：

- Budao ID / 步道 ID
- Sheep ID / 数字羊 ID

可替换凭证：

- 手机号
- 邮箱
- 步道卡
- 未来可能的腕带、二维码、NFC、Wallet 等

原则：卡丢失、补发、手机号变化、邮箱变化，都不能导致数字羊变化。

### 9.5 步道卡的定义

步道卡不是普通会员卡，而是：

> 数字羊在现实世界里的身份锚点。

它把现实世界中发生的同行、营会、给予、牧养、服侍等事件，写回同一个步道身份与数字羊。

### 9.6 卡上“密码”的正式定义

产品与技术上统一称为：**激活码**。

建议规则：

- 每张卡唯一
- 一次性使用
- 激活成功后失效
- 不作为长期登录密码

绑定逻辑：

`Activation Code → Card ID → Budao ID → Sheep ID`

### 9.7 用户状态

建议固定三态：

1. **未注册**：无数字身份
2. **已注册 / 未激活**：已有步道 ID 与数字羊，但未完成现实身份确认
3. **已激活**：步道卡激活码验证成功，卡 / 步道 ID / 数字羊完成绑定

### 9.8 产品含义

注册不是完整终点，而是“数字羊出生”。

激活是网络中的我与现实步道中的我合为同一个身份。

可继续探索的表达：

> 你已经进入牧场。

或更克制：

> 身份已确认。

## 10. 未来现实事件如何写回数字羊

阶段1已确定的长期方向：

- 参加步道 → 留下一次真实同行记录
- 参加营会 → 留下营地经历
- 现实给予 → 留下给予痕迹
- 被牧养 / 被关心 → 风铃或关系痕迹
- 服侍与责任 → 留下责任痕迹

拒绝传统游戏化：

- 不做黄金羊
- 不做等级炫耀
- 不做排行榜
- 不把同行次数转成权力或稀有皮肤

数字羊承载的是：**时间、关系、同行、给予、被关怀。**

## 11. 阶段1已锁定、阶段2默认不得回退的原则

1. 用户就是羊，不是羊的主人。
2. 数字羊不是 avatar / pet / skin。
3. 牧场总览看群体与关系；自我聚焦看自己。
4. 功能优先世界化，不做普通 App 模块套像素皮肤。
5. 不显宗教性的表层视觉。
6. 25只羊羊群视觉基线已通过，不随意改动。
7. v20 河流、独木、水光、瀑布为最新视觉基线。
8. 注册先于步道卡；注册即生成数字羊。
9. 步道卡是现实身份确认，不是账号本体。
10. 必须完成步道卡激活码与数字羊的一一绑定，才进入正式激活状态。
11. 步道 ID / Sheep ID 是长期身份核心；手机号、邮箱、卡等都是可替换凭证。
12. 卡可补发，羊不变。
13. 激活码一次性，不作为长期密码。
14. “身份不是权力升级，而是责任痕迹。”
15. “能成为世界里的东西，就绝不做成按钮。”

## 12. 阶段2起点

阶段2不再以“把牧场画得更漂亮”为主要任务，而是开始解决：

**数字牧场怎样从一个成立的世界，变成一个真正可持续运行的用户系统。**

阶段2优先需要设计的架构问题：

- 注册入口与注册流程
- 步道 ID / Sheep ID 的生成与永久绑定
- 未激活羊与已激活羊在牧场中的区别
- 步道卡发行、Card ID、一次性激活码生成
- 卡与数字羊的认领 / 绑定流程
- 丢卡、补卡、换手机号、换邮箱后的身份连续性
- 现实活动如何安全地写回数字羊
- 当前纯前端原型如何平滑演进到真实持久化数据
- 如何在不破坏“数字牧场世界感”的前提下完成注册、激活与身份确认

阶段2开发必须继续遵循：**先产品逻辑，再数据结构，再交互，最后才是界面。**
