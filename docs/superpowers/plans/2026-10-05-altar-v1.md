# 祭坛 V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 `tony` 增加唯一的 steward 权限、Tent 右下角房角石入口，以及可查看全部路线并执行退回/暂停/锁定/恢复且全程留痕的“祭坛”监管空间，同时不破坏现有 Tent → route → calendar → slot → public page 主链。

**Architecture:** 在现有 publisher 会话上增加服务端可验证的 `steward` 能力；监管状态与 `routes.json` 分离，新增独立监管数据与审计记录；公共路线投影在读取时结合监管状态过滤 `paused`，发布接口在写入前检查 `locked`；祭坛页面通过受保护 API 读取全量路线与监管状态。Tent 仅根据 `/api/auth/session` 返回的服务端能力渲染房角石入口。

**Tech Stack:** Node.js CommonJS / Vercel Serverless Functions / 静态 HTML + CSS + Vanilla JS / GitHub Contents API / Node test runner

**Spec:** `docs/superpowers/specs/2026-10-05-altar-v1-design.md`

## Global Constraints

- V1 中仅 `tony` 获得 steward 权限。
- 房角石只在 Tony 登录 Tent 成功后出现，位置为 Tent 内部右下角，不与“步 / 道 / 祷”并列。
- 前端可见性不能代替服务端授权；所有祭坛数据与动作接口必须验证 steward。
- `routes.json` 继续只保存路线事实和带领人归属，不保存监管状态。
- 监管状态与审计必须独立存储，并按 `routeId` 关联。
- 祭坛故障不得阻断普通带领人的正常登录、创建与发布主链。
- 不提供永久删除。
- 不修改首页动画、数字牧场或其他非祭坛页面。
- 祭坛 UI 必须延续 Tent 美学：安静、克制、低对比、无传统 Dashboard/KPI 风格。

## Review Focus

- 非 Tony 的有效 publisher 会话访问祭坛 API 时必须得到 403，而不是因为已有登录态被误授权。
- Tony 会话过期或伪造 `steward` 客户端字段时仍必须由服务端拒绝。
- `paused` 只能影响公共展示，不能删除 canonical route，也不能阻止日历历史记录存在。
- `locked` 必须阻止对应带领人后续修改，但不能阻断其他带领人发布自己的路线。
- 监管数据读取/写入失败时，公共路线读取与普通 Tent 发布必须有明确降级行为，避免祭坛成为单点依赖。
