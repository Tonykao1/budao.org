# 数字牧场｜捏羊身份引擎 V2 设计规范

日期：2026-10-11
状态：待用户书面审阅

## 1. 目标

把当前“羊毛颜色 + 脸色 + 记号”的简单配置器，升级为真正的居民身份生成流程。

它不是宠物创建器，也不是换装游戏。羊就是用户本人；捏羊的目的，是让用户在进入44只基础羊群后，能够凭视觉特征认出“我”。

成功标准：

- 第一次进入的人可以用极少文字完成整个流程。
- 不依赖中文也能理解主要操作，适合国际用户。
- 用户生成的羊足够可爱、多元、可辨认，但不幼稚、不花哨。
- 同一份羊身份数据贯穿：捏羊预览 → 从天而降 → 44+1羊群 → 抓羊与放置 → 后续头像/卡片/功能区。
- 旧居民羊继续可显示，不因V2上线而失效。

## 2. 核心原则

### 2.1 文字最小化

界面文字是最后手段，不是第一手段。

能用图形表达，不显示文字；需要语义时优先放入 `aria-label`、语言包、悬停/长按辅助，而不是常驻界面。

第一屏固定只显示：

> 你

不显示副标题，不显示“这就是你”，不解释“不是宠物”。

主操作优先使用一个明确的 `→` 进入符号，而不是“开始”。

最终确认优先使用 `✓`，而不是“这就是我 / 进入牧场”。

### 2.2 国际化不是双语堆字

- 主界面图标优先。
- 文本标签默认隐藏或最小化。
- 所有交互均有 `aria-label`，由 locale 字典提供。
- 第一版至少准备 `zh-CN` 与 `en` 语言键结构，但视觉不依赖两种语言同时出现。
- 布局不得依赖中文字宽，必须允许英文、法文、德文等更长字符串。

### 2.3 可爱但不幼稚

视觉关键词：温暖、柔和、像素、安静、轻微喜乐、具有生命感。

避免：

- 宠物装扮感
- 大量饰品
- 夸张卡通表情
- 商业小游戏式奖励动效
- 彩虹化、闪亮化、过度拟人化

### 2.4 羊 = 用户

用户界面避免：

- “我的羊”
- “领养”
- “宠物”
- “获得一只羊”

内部变量可继续使用 `sheep`、`saveSheep` 等技术命名以降低迁移风险。

## 3. 流程结构

V2 使用4屏流程，但只有第一屏和最终确认屏具有明确的“阶段感”。中间两屏在视觉上更像连续捏制，不做传统向导表单。

### 屏1：你

画面：

- 中央一只尚未完整定型的像素羊轮廓。
- 页面唯一常驻标题：`你`
- 页面底部/中央仅一个 `→`。

行为：

- 点击 `→` 进入捏制。
- 无解释性副标题。
- 无“开始认识自己”等按钮文字。

### 屏2：基础形态

中央始终显示实时大羊预览。

开放4个基础维度：

1. 羊毛颜色
2. 脸部颜色
3. 羊毛轮廓
4. 身形

交互：

- 四个维度用图形入口表示。
- 点维度图标后，底部/侧边出现该维度视觉样本。
- 点样本后，中央羊立即变化。
- 不使用 `<select>`、传统 radio 文本列表或说明段落。

### 屏3：个体特征

继续使用同一只实时预览羊，不切换成另一种视觉风格。

开放4个识别维度：

5. 耳朵
6. 表情
7. 记号
8. 额前毛型

同时提供一个小型随机图标（骰子/轻量随机符号），用于“给我一个组合”，但随机结果仍可继续微调。

### 屏4：确认

画面只保留完成后的羊。

- 无“这就是我”标题。
- 无解释段落。
- 主操作仅 `✓`。
- 可保留一个很小的返回箭头用于回到捏制，不写“返回修改”。

点击 `✓`：

1. 保存 V2 羊DNA。
2. 将 V2 DNA 发送给牧场核心居民引擎。
3. 启动从天而降动画。
4. 羊群进入44+1。
5. 后续继续使用已验收通过的找羊 / 五指牧者之手 / 拖放 / 0.90秒空间羊叫系统。

## 4. 八个视觉维度

V2第一版维度固定如下。

### 4.1 羊毛颜色 `woolColor`

建议 10–12 个基础色，保持自然和全球审美：

- 云白
- 米白
- 奶油
- 麦色
- 浅灰
- 银灰
- 暖灰
- 淡褐
- 深灰
- 炭黑
- 可加两种低饱和柔和色作为少量个性选项

颜色不是用文字列表选择，而是直接显示羊毛样本。

### 4.2 脸部颜色 `faceColor`

建议 8–10 个自然色阶，从浅米到深炭，确保与不同羊毛颜色有足够组合差异。

### 4.3 羊毛轮廓 `woolShape`

第一版 4 种：

- clean：较整齐
- soft：柔和自然
- fluffy：更蓬松
- curly：局部卷曲感

差异必须体现在像素轮廓，而不是只改内部纹理。

### 4.4 身形 `bodyShape`

第一版 4 种：

- small：小巧
- standard：标准
- round：更圆
- tall：略高

“身形”是造型比例，不改变牧场远近透视规则。牧场内最终显示大小仍由 y 位置决定。

### 4.5 耳朵 `ears`

第一版 4 种：

- small
- medium
- droop
- perk

必须保证远景缩小时仍能形成可辨识的轮廓差异。

### 4.6 表情 `expression`

第一版 4 种：

- calm
- gentleSmile
- curious
- joyful

只通过眼睛 / 嘴部极少像素变化体现，不做拟人脸。

### 4.7 记号 `marking`

第一版建议 7 种：

- none
- forehead
- cheek
- facePatch
- backPatch
- socks
- earMark

记号必须保持“自然羊的花纹”，不变成贴纸或装饰。

### 4.8 额前毛型 `forelock`

第一版 5 种：

- none
- tuft
- curl
- side
- cloud

这个维度用于提高44只羊中肉眼辨识效率。

## 5. 羊DNA V2

### 5.1 数据策略

保留现有 `pasture_sheep` 的：

- `body_color`
- `head_color`
- `marking`

它们继续用于兼容旧居民、旧读取逻辑和必要回退。

新增：

- `appearance_version integer NOT NULL DEFAULT 1`
- `appearance_v2 jsonb`

V2示例：

```json
{
  "version": 2,
  "woolColor": "cloudWhite",
  "faceColor": "warmGray",
  "woolShape": "fluffy",
  "bodyShape": "round",
  "ears": "droop",
  "expression": "curious",
  "marking": "forehead",
  "forelock": "curl"
}
```

### 5.2 兼容规则

- `appearance_version = 1` 或 `appearance_v2 IS NULL`：继续按旧3维方式渲染。
- `appearance_version = 2`：使用V2渲染器。
- 保存V2时，同时回填旧 `body_color / head_color / marking`，保证旧逻辑不会立刻失效。
- 不要求现有两个测试居民立刻重捏；V2开发和验收期间可继续保留旧数据。
- 后续如决定让早期测试居民重捏，应单独设计迁移/重置动作，不在本次自动删除任何记录。

## 6. 渲染架构

必须避免“捏羊页面画一种羊，牧场核心画另一种羊”。

建立一个共享的视觉定义层，建议拆成：

- `pasture-sheep-dna.js`：DNA校验、默认值、随机生成、V1→兼容映射。
- `pasture-sheep-renderer.js`：根据DNA输出像素几何/rects。
- `pasture-live.js`：仅负责捏羊流程、状态、保存，不重复定义羊身体几何。
- `pasture-resident-core.js`：继续负责牧场中的第45只羊，但调用共享 renderer。

要求：

- 捏羊预览与牧场最终羊必须来自同一个 renderer。
- 精确像素命中 mask 也从同一 renderer 的几何生成。
- 不为V2重新引入外层 residentCanvas。

## 7. 随机生成

随机图标只做一个动作：生成一组合法的8维 DNA。

规则：

- 不随机出视觉冲突明显的组合，例如深色脸 + 极深羊毛导致脸完全不可辨。
- 随机不是最终提交，用户仍可继续修改任意维度。
- 不使用“稀有度”“抽卡”“奖励”等游戏化概念。

## 8. 可访问性与国际化实现

所有图形选项必须：

- 可键盘聚焦。
- 有 `aria-pressed` / `aria-selected` 状态。
- 有 locale 驱动的 `aria-label`。
- 颜色不能成为唯一识别方式；被选状态还必须有边框/像素框/形状反馈。
- 移动端点击目标不少于约44 CSS px。

语言包第一版至少定义：

- `zh-CN`
- `en`

但主视觉不依赖常驻文字，语言包主要服务邮箱/验证码、错误提示、辅助技术和必要标签。

## 9. 移动端

- 中央羊预览必须保持最大视觉优先级。
- 维度入口允许横向滚动或两行紧凑网格，但不挤压羊预览。
- 选项面板从底部升起优先于右侧栏。
- 不允许出现浏览器原生 select 风格。

## 10. 错误与保存

- 在最后 `✓` 前，所有变化只存在前端临时 state，不连续写数据库。
- 用户刷新/误退时，可在 `sessionStorage` 保存未完成DNA草稿；不把未确认草稿视为正式羊身份。
- 保存失败时停留在确认屏，羊不从天而降。
- 只有 API 明确保存成功后才触发 arrival。
- arrival 不重复：已有V2正式身份正常登录时直接进入羊群，不重新从天而降。

## 11. 测试门禁

必须新增自动测试，至少覆盖：

1. 数据库兼容：V1记录仍能读取。
2. V2 DNA 八维完整保存与读取。
3. 捏羊UI不出现 `<select>`。
4. 第一屏可见文案严格只允许 `你`（错误/辅助文本除外）。
5. 最终确认主操作为 `✓`。
6. 预览 renderer 与牧场 renderer 是同一共享模块。
7. 随机DNA始终通过 schema 校验。
8. 旧抓羊 / 夜景 / 脚点放置 / 0.90秒空间音频门禁继续通过。
9. 不删除或重置现有居民数据。

## 12. 本次明确不做

为了保持V2第一版聚焦，本次不做：

- 帽子、衣服、项链等装饰物
- 性别选择
- 人种/肤色映射
- 名字显示
- 羊的评分、稀有度、排行榜
- AI根据自拍生成羊
- 自动“帮我找到自己”定位
- 多套羊身份切换

## 13. 验收标准

用户第一次进入时，体验应当是：

`你 → 看见羊 → 点图形 → 羊立即变化 → 继续捏 → ✓ → 从天而降 → 44+1 → 在羊群中认出自己`

如果用户需要阅读说明文字才能理解怎么继续，设计失败。

如果捏羊预览与牧场中的羊明显不是同一个个体，设计失败。

如果不同用户最终仍主要只是“同一个模板换颜色”，设计失败。
