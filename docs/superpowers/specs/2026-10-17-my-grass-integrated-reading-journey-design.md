# 《我的牧草》一体化读经 Journey 设计稿

日期：2026-10-17
状态：设计待用户书面审阅
适用分支：`feat/my-grass-cuv-shen-bible-v1`

## 1. 产品目标

《我的牧草》不是“经文选择 + 录音 + 灵修笔记”的功能拼接，而是帮助全球基督徒真实读经、领受神话语并留下真实阅读轨迹的平台。

本次重构的核心是：

- 选择经文不等于读过。
- “完成阅读”不再由用户事先声明。
- 读经与本人原声不再是两个独立对象。
- 用户点击第一节经文后，读经与录音同时开始。
- 用户逐节点击前进，录音不中断，并留下真实的经节时间节点。
- 用户点击“结束今日读经”后，系统根据实际经过的经节生成本次读经范围。
- 系统记录阅读行为与经节进程的一致性，但不声称验证“每个字都读对了”。

## 2. 旧流程要淘汰的部分

旧流程：

1. 用户先选择经文范围，例如创 1:1–20。
2. 点击“完成本次阅读”。
3. 再单独录音。
4. 再点击“链接”把音频与经文绑定。

问题：系统无法知道音频实际是否覆盖 1–20 节，可能只读了 1–2 节却被绑定到 1–20 节。

因此以下旧概念退出核心流程：

- “完成本次阅读”作为事先声明动作。
- 独立的“开始录音”动作。
- `🔗 链接录音`动作。
- 录音与 reading session 平行、事后绑定的模型。
- 淡草痕作为已读状态的主要视觉语言。

## 3. 新的核心对象：Reading Journey

一次“今日读经”应被视为一个整体对象，包含：

- 译本
- 书卷 / 章节
- 起始经节
- 实际结束经节
- 连续本人原声音频
- 每节进入时间点
- 每节结束时间点
- 开始时间
- 结束时间
- 总时长
- 完成状态

示意：

```text
Reading Journey
创世记 1:1–7
00:00 → 03:18

1节 00:00.000 → 00:11.420
2节 00:11.420 → 00:29.100
3节 00:29.100 → 00:42.800
...
7节 02:11.000 → 03:18.000
```

音频与经节时间线从 Journey 创建时就是一个整体，不再需要“链接”。

## 4. 第一阶段完整工作流

### 4.1 浏览章节

用户先翻到某一章，例如创世记 1 章。

浏览、滚动、切换译本本身都不创建正式阅读记录。

左页底部的“今日读经状态区”在未开始时保持安静：

> 点一节经文，开始今日读经

### 4.2 点击第一节 = 开始今日读经

用户点击任意一节，例如创 1:1。

系统执行：

1. 将该节设为起始节。
2. 请求麦克风权限（若尚未授权）。
3. 授权期间状态区显示“正在开启麦克风…”。
4. 授权成功后立即开始连续录音。
5. 记录 Journey `startedAt` 与音频起点 `0`。
6. 当前节进入“正在读”视觉状态。
7. 右页录音设备进入明确 REC 状态。
8. 左页状态区显示：

> ● 正在读经 · 创 1:1 · 00:00　　■ 结束今日读经

如果麦克风授权失败，本次 Journey 不进入正式录音状态；系统应明确告知失败，不得伪装为“正在读经”。

## 5. 经节推进规则

### 5.1 正常推进

用户读完当前节后，直接点击下一节经文。

例如从创 1:1 点击创 1:2：

- 录音绝不中断。
- 在点击瞬间记录 1:1 的结束时间。
- 同一时间点记录 1:2 的开始时间。
- 1:1 进入“已读”。
- 1:2 进入“正在读”。
- 左页状态区更新为“创 1:2”。

### 5.2 连续性约束

正常读经模式只允许顺序进入下一节。

如果当前正在读第3节：

- 点击第4节：正常推进。
- 再点第3节：不推进，不重复封存时间点。
- 直接点第8节：不允许把第4–7节自动算作已读。

提示：

> 当前正在读第3节，请从下一节继续。

本轮不设计“跳读模式”。若未来需要，作为独立模式另行设计，不能污染正常读经记录的可信度。

## 6. 录音中的明确视觉反馈

用户必须在任何时刻都明确知道：麦克风是否真的在录音、当前读到哪一节、如何结束。

### 6.1 左页“今日读经状态区”

利用原先“完成本次阅读”所在区域重新设计，不增加古卷中央悬浮控件，不破坏左右页完整性。

录音中固定显示：

- 实心 REC 点，允许极轻微呼吸，不闪烁。
- 文案“正在读经”。
- 当前经节，例如“创 1:7”。
- 实时计时，例如“02:14”。
- 明确按钮“■ 结束今日读经”。

### 6.2 右页录音设备

右页复古录音机保留，但职责调整为设备状态反馈，而不是读经流程的主控制器：

- REC 灯明确亮起。
- 波形持续活动。
- 时间运行。
- 不再提供独立的“开始录音”。
- 不再提供“链接录音”。

左页负责“读经状态与结束”，右页负责“设备确实正在记录”的物理反馈。

## 7. 经文视觉：淘汰淡草痕，改为“页边读痕”

现有淡草痕视觉不再保留。原因：不明显、不高级、半遮半掩，无法清晰表达阅读进度。

新的视觉分成三种状态。

### 7.1 未读

- 保持普通圣经排版。
- 正文正常墨色。
- 节号保持普通层级。
- 不加底色、不加横线。

### 7.2 已读

- 正文尽量保持出版级正常排版，不整段加粗。
- 节号进入更明确、更深的已读状态。
- 左侧页边出现短而干净的竖向“读痕”。
- 连续已读经节形成安静、清晰的纵向阅读轨迹。
- 读痕是抽象阅读标记，不画成具象草叶，不使用荧光笔式背景。

### 7.3 当前正在读

- 当前节正文进入明显聚焦状态。
- 当前节号比已读节号再强一档。
- 左侧页边读痕在当前节位置形成更明确的“当前指针”。
- 不依赖单纯的 `font-weight: 900`，因为中文楷体在不同设备上的字重支持不稳定。
- 不变色、不闪烁、不逐字追光、不做娱乐型卡拉 OK。

示意：

```text
│  1  起初，神创造天地。
│  2  地是空虚混沌……
│  3  神说，要有光……

▌  4  神看光是好的……      ← 当前正在读
   5  神称光为昼……
   6  神说，诸水之间……
```

真实实现使用与古卷一致的精细页边线条，而不是字符图形。

## 8. 读痕实时生长

读痕不是 Journey 结束后一次性出现，而是实时形成。

例如：

- 正在读第1节：第1节为当前状态。
- 点击第2节后：第1节立即进入已读读痕，第2节成为当前状态。
- 点击第3节后：第1–2节形成连续已读轨迹，第3节成为当前状态。

用户在读经过程中就能看到“已经走过哪里、现在在哪里、后面还没有读到哪里”。

## 9. 结束今日读经

用户点击左页状态区的：

> ■ 结束今日读经

不直接结束，而是进入古卷内轻量确认层。

确认内容：

> 结束今日读经？
> 创世记 1:1–7 · 03:18
>
> 继续读　　结束

规则：

- “继续读”为安全选项，不改变录音与时间线。
- 只有明确点击“结束”，才真正停止录音。
- 点击“结束”时，系统封存当前最后一节的结束时间。
- 自动计算本次实际阅读范围。
- 保存 Journey 时间线。
- 停止 REC 状态。
- Journey 进入 completed。

## 10. 完成后的状态

结束后，左页显示本次真实阅读结果，例如：

> 今日读经完成 · 创世记 1:1–7 · 03:18

完成后允许：

- 回听本人原声。
- 播放时根据真实 verse timestamps 聚焦对应经节。
- 进入下一阶段“沉淀 / 领受”。

播放跟随不再根据文字长度估算，而直接使用当次 Journey 留下的真实时间节点。

## 11. 回听跟随

回听时：

- 读取真实 verse timeline。
- 当前音频时间落在哪个经节区间，就聚焦哪一节。
- 经节切换完全跟随本人当时真实阅读节奏。
- 暂停时保留当前节。
- 播放结束后退出回听聚焦，恢复完成后的阅读视觉。

本轮不引入语音识别。

系统只能确认：

- 用户在某一时间区间将该节设为当前阅读节。
- 麦克风在同一时间区间持续录音。

系统不能声称：

- 已验证每个字都读对。
- 已验证用户实际发音内容与经文逐字一致。

未来若加入语音识别，只能作为“辅助自动对齐”，不能成为正常读经记录的唯一判据。

## 12. 异常与中断

### 12.1 麦克风授权拒绝

- 不创建正式 Journey 录音段。
- 当前节不得伪装为“正在录音”。
- 明确提示用户未取得麦克风权限。

### 12.2 录音过程中设备/浏览器异常

如果 MediaRecorder 异常停止：

- 立即退出 REC 视觉。
- 停止允许经节继续推进。
- 保留已经确认的经节时间节点与可恢复的音频数据。
- 提示“录音已中断”，让用户选择重新开始本次读经或结束当前可恢复部分。

具体恢复策略在实现计划中进一步细化，但不得静默继续记录“已读”。

### 12.3 用户误点结束

使用“继续读 / 结束”确认层保护当前 Journey。

### 12.4 页面切换 / 离开

录音中不允许静默切换到其他模块、档案或新开一页。应先提示用户结束或继续当前读经。

## 13. 数据可信度原则

本次重构的关键不是“提高录音功能”，而是提高读经记录的真实性。

系统应始终遵守：

1. 浏览 ≠ 读过。
2. 选中 ≠ 读过。
3. 当前节只有在 Journey 正在录音并进入下一节/结束后，才能成为“已读”。
4. 不允许通过跳到更远经节自动补齐中间经节。
5. 实际阅读范围由真实逐节推进生成，不由用户事先声明。
6. 音频与经文时间线共同属于一次 Reading Journey。
7. 不做超出证据范围的语音正确性声明。

## 14. 全球化约束

底层以稳定 verse ID 工作，不写死中文或 ESV。

视觉与交互必须可适配：

- 中文
- 英文
- 西班牙语
- 韩语
- 阿拉伯语及 RTL
- 其他合法接入译本

“页边读痕 + 当前指针 + 经节时间线”优先采用结构化位置与状态，不依赖某一种字体的字重能力。

## 15. 实现范围边界

本轮设计只重构“今日读经”第一阶段及其完成后的回听跟随。

不在本轮扩大到：

- 自动语音识别
- 逐字评分
- 发音纠正
- 云端音频上传
- 公开发布
- 跳读模式
- 多章节连续 Journey

继续保留“沉淀 / 牧养”后续阶段，但它们消费新的 completed Reading Journey，而不参与 Journey 录音过程。

## 16. 验收标准

实现完成后，至少满足：

1. 点击第一节经文后直接请求权限并开始录音，无独立“开始录音”步骤。
2. 点击下一节时录音不中断。
3. 只允许连续下一节推进，不允许跳过中间节并算作已读。
4. 左页原“完成本次阅读”区域改为持续可见的“今日读经状态区”。
5. 录音中用户始终能看到 REC 状态、当前经节、计时和结束按钮。
6. 右页录音设备持续明确反馈正在录音。
7. 淡草痕彻底移除。
8. 已读、当前、未读三种状态一眼可辨，同时保持圣经阅读的克制与高级感。
9. 点击结束出现“继续读 / 结束”确认。
10. 结束后实际经文范围由真实推进结果生成。
11. 每节都有真实时间节点。
12. 回听时根据真实时间节点逐节跟随，不再使用文字长度估算。
13. 旧“链接录音”动作退出核心流程。
14. 不声称验证逐字朗读正确性。
15. 原有左/右古卷结构完整，不新增中央悬浮控制条。

## 17. 设计结论

新的第一阶段不再是“选经文 → 完成阅读 → 录音 → 链接”。

它成为一条连续、真实、可回听的读经 Journey：

> 翻到章节 → 点击第一节 → 录音与读经同时开始 → 逐节点击向前、录音不断 → 页边读痕实时生长 → 随时明确看到正在录音与结束位置 → 结束确认 → 自动封存真实阅读范围与经节时间线 → 回听时按真实节奏重新进入那次读经 → 进入领受。

产品记录的不是“用户说自己读过什么”，而是“这次读经真实走到了哪里”。
