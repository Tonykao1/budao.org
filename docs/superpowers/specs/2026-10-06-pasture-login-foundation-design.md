# 数字牧场登录基础设施设计（G1）

日期：2026-10-06
分支：`integration/pasture-registration-20261005`

## 1. 设计原则

数字牧场后续开发必须遵守一条不可破坏的原则：**只做加法，不做替换。**

已经通过的完整数字牧场视为冻结母版。任何登录、注册、身份、羊只能力都只能嵌入母版，不能重画、搬家、隐藏、删除或降级既有功能。

受保护资产包括但不限于：
- 天空七功能区；
- 正式头像 / 身份卡；
- 小铺；
- 小匣；
- 步道卡；
- 已统一的“收起 ×”返回体系；
- 天气、昼夜、月相与景观；
- 44 只基础羊；
- 横屏 / 竖屏布局；
- 返回步道首页树杈；
- 已通过的大手、拖放与 `baaa01.mp3` 交互。

任何新增提交如果导致上述任一资产消失、位置异常、样式回退或功能失效，直接视为回归失败。

## 2. G1 目标

G1 只新增以下能力链：

`邮箱登录 → 邮箱验证码 → 首次注册识别 → 捏羊 → 羊从天落下 → 成为第45只羊 → 每天在羊群中找自己 → 五指大手识别并可拖放`

老用户再次登录时，不允许再次捏羊，必须直接恢复原身份和原羊外观。

## 3. 当前已有能力

当前代码已经具备以下后端基础：
- `pasture_users`：邮箱哈希唯一，一个邮箱对应一个用户；
- `pasture_email_verifications`：6 位验证码、有效期与尝试次数；
- `pasture_sessions`：服务端 Session；
- `pasture_sheep`：一个用户唯一对应一只羊；
- 邮箱原文使用 AES-256-GCM 加密保存；
- Session token 只以哈希形式入库；
- 登录 Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`；
- 验证成功后后端会返回现有羊，从而可判断首次注册或老用户；
- 羊的身体颜色、头部颜色与花纹已经在服务端持久化。

## 4. 身份模型

### 4.1 永久身份

一个用户由以下永久链路定义：

`标准化邮箱 → email_hash → pasture_user.id → pasture_sheep.user_id`

规则：
- 同一邮箱永远对应同一个 `pasture_user.id`；
- 一个用户只能有一只羊；
- 羊的外观属于永久身份数据；
- 换设备、换浏览器后，只要重新通过邮箱验证码登录，仍然恢复同一用户和同一只羊。

### 4.2 Session

Session 保持期改为 **365 天**。

含义：
- 账号本身永久存在；
- 365 天只是“免重复验证码登录”的最长时长；
- 用户主动退出时立即撤销当前 Session；
- Session 过期后，重新通过邮箱验证码即可恢复原身份与原羊；
- 不因为 Session 过期删除任何用户或羊数据。

本阶段不做“无限自动续期”，避免增加不必要复杂度。365 天已经足够覆盖长期回访体验。

## 5. 首次注册与再次登录分流

邮箱验证码验证成功后：

### 首次用户
若 `pasture_sheep` 不存在：
1. 创建 / 找到用户；
2. 创建 Session；
3. 返回 `needsSheep: true`；
4. 前端进入已通过的捏羊流程；
5. `saveSheep` 成功后写入服务端；
6. 羊执行一次“从天落下”动画；
7. 当天生成并保存第45只羊的位置。

### 老用户
若 `pasture_sheep` 已存在：
1. 创建新 Session；
2. 返回 `needsSheep: false` 与现有羊；
3. 跳过捏羊；
4. 直接进入完整数字牧场；
5. 读取当天第45只羊的位置；
6. 若当天尚未生成，则生成并保存。

## 6. 每天找羊规则

这是已经确定的产品原则：**每天找羊。**

第45只羊的规则：
- 羊的身份和外观永久不变；
- 每天进入新的一天后，位置重新生成；
- 同一天内，初始位置保持稳定；
- 当天用户找到并拖动自己的羊后，新的位置应保存；
- 同一天换设备重新登录，应看到同一位置；
- 到第二天，系统忽略前一天位置并生成新的当天位置；
- 不提供“找到我的羊”快捷入口；
- 只有自己的羊有效像素触发五指大手。

## 7. 每日位置数据模型

新增一张独立表，不修改 `pasture_sheep` 的永久身份职责。

建议表名：`pasture_sheep_daily_positions`

字段：
- `id uuid primary key`；
- `user_id uuid not null references pasture_users(id) on delete cascade`；
- `date_key text not null`，格式 `YYYY-MM-DD`；
- `mode text not null`，值为 `landscape` / `portrait`；
- `x numeric not null`；
- `y numeric not null`；
- `flip boolean not null default false`；
- `created_at timestamptz not null default now()`；
- `updated_at timestamptz not null default now()`。

唯一约束：

`unique(user_id, date_key, mode)`

说明：
- 横屏与竖屏坐标体系不同，分别保存；
- 当天同一模式只有一个位置；
- 用户拖动后做 upsert；
- 次日使用新 `date_key`，自动生成新位置；
- `localStorage` 仅允许做前端缓存，不再是真实来源。

## 8. 日期规则

每日找羊的“天”统一以牧场当前解析到的时区计算。

优先顺序：
1. 当前牧场环境状态中的时区；
2. 无法取得时，默认 `Asia/Shanghai`。

同一页面里的天气、昼夜、羊群日期与第45只羊 `date_key` 必须使用同一时区来源，避免 VPN 节点导致多个系统各算各的日期。

## 9. API 设计

继续复用当前 `/api/pasture-auth` 入口，不新建一套认证系统。

现有 action 保留：
- `requestCode`
- `verifyCode`
- `saveSheep`
- `logout`

新增两个受 Session 保护的 action：

### `getDailySheepPosition`
请求：
- `dateKey`
- `mode`

行为：
- 验证 Session；
- 查找当天位置；
- 存在则返回；
- 不存在则由服务端或共享纯函数生成安全初始位置并写入后返回。

### `saveDailySheepPosition`
请求：
- `dateKey`
- `mode`
- `x`
- `y`
- `flip`

行为：
- 验证 Session；
- 验证坐标合法范围；
- upsert 当日位置；
- 只允许修改当前登录用户自己的位置。

## 10. 初始位置生成

位置生成必须满足：
- 不落入河道；
- 不落到独木桥；
- 尽量避免与基础 44 只羊重叠；
- 必须处于可见区域；
- 保持正确透视尺度；
- 不使用“永远固定某个安全点”的方式；
- 同一个用户、同一天、同一模式应生成稳定结果。

建议采用确定性 seed：

`hash(user_id + ':' + date_key + ':' + mode)`

服务端和前端应共享同一套纯逻辑，避免两个实现漂移。

## 11. 完整牧场接入策略

**完整牧场母版优先，注册运行层退回为能力层。**

禁止继续由 `pasture-resident-runtime` 动态重建以下 UI：
- 七功能按钮；
- 身份卡；
- 小铺；
- 小匣；
- 步道卡；
- 返回 / 收起体系。

新的 resident 代码只能负责：
- 查询登录状态；
- 首次注册流程；
- 第45只羊绘制；
- 每日位置同步；
- 大手命中与拖放；
- 登录 / 登出状态通知给完整牧场母版。

完整牧场母版根据认证状态决定：
- 未登录：隐藏已有功能入口；
- 已登录：显示原来已经通过的功能区和身份体系；
- 不重新创建任何视觉组件。

## 12. 头像 / 身份卡接入

正式头像和身份卡使用原已通过设计。

G1 只把真实身份数据灌入原组件：
- `resident_id`；
- 掩码邮箱（如确有需要展示）；
- 羊的头像 / 外观；
- 未来昵称等字段暂不新增，除非已有母版明确存在。

小匣仍保持原正式入口关系，不迁移到七主功能。

## 13. 登出规则

主动退出后：
- 撤销当前 Session；
- 清除 Session Cookie；
- UI 回到未登录牧场；
- 天空功能区按既定规则隐藏；
- 第45只羊从当前视图移除；
- 基础 44 只羊保留；
- 用户、羊外观、历史每日位置数据均不删除。

## 14. 错误恢复

必须覆盖：
- 邮箱格式错误；
- 验证码过期；
- 验证码错误；
- 验证次数锁定；
- 发送频率限制；
- 邮件服务不可用；
- 数据库不可用；
- Session 失效；
- 保存羊重复点击；
- 保存位置网络中断；
- 页面刷新发生在“验证成功但尚未捏羊”之间；
- 页面刷新发生在“捏羊成功但动画尚未结束”之间。

原则：任何异常都不能产生第二个用户、第二只羊或半注册孤儿状态。

## 15. 安全约束

保留并继续使用当前安全策略：
- 同源 POST；
- IP / 邮箱速率限制；
- 验证码哈希存储；
- Session token 哈希存储；
- 邮箱加密存储；
- `HttpOnly` + `Secure` + `SameSite=Lax` Cookie；
- 所有位置读写均以 Session 中的 user_id 为准，绝不接受前端提交任意 user_id；
- 坐标与 mode 做服务器端白名单验证。

## 16. 回归验收清单

每一个登录相关提交都必须同时验证：

### 旧功能不可少
- 天空七功能区仍为已通过视觉与位置；
- 正式头像 / 身份卡存在；
- 小铺存在；
- 小匣存在；
- 步道卡存在；
- 所有“收起 ×”保持统一；
- 天气 / 昼夜 / 月相正常；
- 基础 44 只羊正常；
- 横屏 / 竖屏正常；
- 返回步道首页树杈正常；
- 大手仍为五指，只命中自己的羊有效像素；
- `baaa01.mp3` 仍为唯一羊叫音效。

### 新登录能力必须通过
- 新邮箱首次登录只创建一个 user；
- 首次用户只捏一次羊；
- 老用户不再捏羊；
- 同邮箱跨设备恢复同一 user / sheep；
- Session 最长保持 365 天；
- 登出立即失效；
- 当天位置跨设备一致；
- 拖动后当天位置同步；
- 次日重新分布；
- 未登录永远只有 44 只羊；
- 已登录显示 44 + 自己。

## 17. 非目标

本阶段不做：
- 社交关系；
- 好友扫描；
- 同路伙伴正式数据模型；
- 昵称编辑；
- 头像上传；
- 多只羊；
- 羊的永久固定位置；
- 自动寻找自己的羊；
- 无限 Session 自动续期；
- 重做任何已经通过的牧场 UI。

## 18. 完成标准

G1 登录基础设施完成的定义不是“能收到验证码”，而是：

**用户在完整数字牧场中完成一次注册后，长期拥有一个稳定身份和一只稳定外观的羊；每天重新在羊群中寻找自己；当天跨设备位置一致；老用户再次进入无需重复捏羊；同时过去已经通过的数字牧场功能一个都没有丢。**
