# 营火之地：步道照片与评论回顾 · 内容维护规范

## 一、产品定位

**营火之地只记录“步道”本身。** 这是步道事工的影像与评论档案，不是对外项目招商页、公益机构名录或站内所有事工导航。

用户浏览路径为：**照片 → 原声评论 → 时间足迹 → 分享自己的步道回忆**。

全站主导航保持原样，但营火之地主体不引入童行、牧场、路上星火机构卡片等内容。

## 二、数据来源

- 页面：yhzd.html
- 样式：campfire.css
- 功能：campfire.js
- 人工策展：data/campfire-archive.json
- 过往发布线路：routes.json 与 route-history.json

旧版营火之地拥有 **34 条真实留言**，已原样转入 JSON 的 quotes 字段，并未替任何一条留言补造发言者、时间、活动地点。featuredQuoteIndexes 控制首页优先呈现的六条原话，其余通过“继续听听他们的话”依次浏览。

## 三、照片归档与照片真实性

早期站点只有历次线路发布用的 route.image，**这不是可靠的“当天活动现场照片库”**。页面可以展示它们，但始终必须标记 **线路封面**，不能因线路日期已过去就认定活动确已举行。自 2026-11-04 起，第一组已核对的步道实拍相册为 **261031「鹿皮关·领袖行军」**，10 张照片存储于 campfire-photos/261031/，并按活动归档。 第二组为 **261024「浅山赏秋」**，来自 2026-10-24 舞彩浅山的实拍两张，存储于 campfire-photos/261024/。第三组为 **261010「蟒山·国度·同行」**，2026-10-10 北京昌平蟒山环线活动实拍 6 张，存储于 campfire-photos/261010/。 第四组为 **261003「天津·宝坻·麦浪之约」**，2026-10-03 天津宝坻活动实拍4张（3张同行照片＋1张餐食特写）；管理员要求删去两张餐食照片中含有窗边人物的全景照片，仅保留餐食特写，发布路径为 campfire-photos/261003/。

只有经同工核实并确认可公开展示的实际步道照片，才能写入 albums；**绝不填入未经确认的照片或捏造活动资料。** 261031、261024、261010 与 261003 相册由用户提交并明确批准公开发布，原始 34 条同行留言保持不变。

每个实际相册采用以下结构（只作格式示范，不是实际照片）：

    {
      "id": "unique-route-album-id",
      "date": "2026-11-01",
      "title": "真实活动标题",
      "location": "真实活动地点",
      "published": true,
      "photos": [
        {
          "src": "/campfire-photos/authorized-photo.jpg",
          "alt": "这张照片的客观描述",
          "caption": "经核实的照片说明",
          "approved": true
        }
      ]
    }

- published: true 是相册级别发布开关；每张照片仍需 approved: true。
- 图片建议存放在 campfire-photos/，压缩、去除不必要的 EXIF/GPS 信息；上传前征得图片权利人及可辨认人物的适当同意。
- 尤其注意未成年人、教会聚会参与者、健康与信仰等敏感身份信息；不公开未经同意的人像、昵称、电话号码、位置轨迹。
- 真实照片和线路封面分开展示，视觉上明确标记；照片不自动关联匿名评论。
- 写评论归属前必须核实其具体活动场次、发言许可，不以猜测补写姓名。
- 任何新增相册都要考虑授权撤回和删除请求处理。

## 四、往期线路回顾的含义

“时光里的步道”自动读取现有线路清单，按日期展示已发布的往期线路资料；取消记录会排除。**这只是历史线路索引，不代表活动实际举办。**

只有记录了活动完成证明及照片、评论授权后，才宜将其中某次升级为正式“活动回顾相册”。

## 五、验收与发布

1. 修改 JSON / CSS / JS，在开发分支进行。
2. 运行 node --check campfire.js、node --test test/campfire-page.test.js。
3. 验证桌面和手机：照片图片加载、分类按钮、放大灯箱、上一张/下一张、全部 34 条评论、时间归档、分享。
4. 检查空相册状态：点击“现场照片”，应明确说明尚无经确认的现场图片，不得偷换成线路封面。
5. 正式合并前由负责同工核对照片、评论授权；合并后确认主站、移动端和原有路线功能。

## 六、步道现场照片小脚丫水印（2026-11-06）

管理员已确认标准线稿：`assets/budao-footprint-watermark.svg`。保留透明背景，单色线条根据水印区域的局部明暗自动选择深色或浅色，右下角统一尺寸为照片短边约 9%，距两侧边缘约为短边 3%，线条不透明度约 60%。

- **严格限定现场照片：** `data/campfire-archive.json` 中 `published: true` 的相册，且单张 `approved: true`、`src` 以 `/campfire-photos/` 开头，才允许生成水印。
- **永久保留未经修改的原件：** `campfire-photos/` 不变；`scripts/campfire-watermark.py` 另外生成 `campfire-watermarked/` 中 WebP 格式的图片副本，输出中不携带 EXIF/GPS 元数据，且长边限制为 2400px。
- **只影响照片展示：** 营火之地的画廊、首页影像及放大灯箱使用生成的展示副本；线路封面 `/images/`、`/route-assets/` 一律沿用原图。
- **未来自动化：** 新增或修改已批准的现场照片并推送到 main 后，GitHub Actions 工作流 `.github/workflows/campfire-watermark.yml` 自动同步展示副本；同时移除失去批准或取消发布的对应衍生图片。
- **首次发布的短暂间隙：** 如果自动化暂未生成某张新照片的展示副本，前端可回退原图，并临时以 SVG 覆盖水印；后续发布生成版后，用户保存的图片将包含永久水印像素。
- **内容审核与撤销权：** 仅有水印不代表取得著作权；应继续取得摄影作者以及相关被摄者的授权。撤销照片公开授权时，应从影集数据中撤回并完成生成版清理、部署及 CDN 缓存检查。

**编辑人员日常操作不变：** 仍按原流程上传实拍照片并核实相册与照片的公开授权，提交入库即可。不要手工覆盖源照片，也无需逐张制作水印。


## 七、首屏「三次同行，三段记忆」轮换与影集直达（2026-11-10）

- **来源边界：** 首屏只从已公开的真实活动相册中选择 `published: true`、`approved: true` 的现场照片；历史线路封面不得作为三次实际同行的替代。活动不足三场时宁缺勿滥。
- **独立活动：** 三张照片必须分别来自三场不同活动，每次进入页面重新挑选。优先回避同一标签页中上一次的三场活动，素材池不足时允许必要重复；使用 `sessionStorage` 保存上一次选取的活动与图片路径，数据不上传服务器，不涉及身份识别。
- **零付费 AI 画质预筛：** `scripts/campfire-watermark.py` 在生成水印时同步针对原始照片计算清晰度代理指标、曝光、明暗层次、饱和度、尺寸与画幅适配，保存为 `data/campfire-hero-quality.json`。照片主题由现有的客观文字描述提供少量排序权重；正式首屏只在各场活动较优的照片中随机选择。
- **人工策展优先：** 在单张照片对象上设置 `"heroEligible": false`，可使其继续留在影集但不再成为首屏候选；设置 `"heroScore": 90`（0–100 整数或数值）可人工指定首屏优先级。画质分数只是技术预测，不保证符合所有人的审美；照片授权审核仍是首要条件。
- **交互规则：** 首次点击任一张，原位、原尺寸、原角度升至最上层；再次点击**同一张**，将「沿途影像」切换为现场照片并平滑滚动到该场的照片集群标题。点击另一张则重新开始两次点击的顺序。首次点击原本处于上层的那张也只选择，不会直接跳转。键盘回车/空格可以执行同样操作，系统设置减少动态效果时使用无动画滚动。
- **影集定位：** 影像网格为每个真实活动添加分组标题，但卡片本身、点赞评论、打开灯箱、筛选及分页仍沿用原逻辑。对于最初 72 张照片之外的活动，跳转前会自动扩展展示数量，再滚动到目标。
- **更新流程：** 新照片授权入库后，水印 GitHub Actions 工作流同步重算画质文件并发布；前端在同步间隙可依据已审核图片说明与人工优先级回退选图，不依赖任何 AI API 或 Token。
