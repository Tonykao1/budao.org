## 1. 数字牧场的终极异象

创始人的表述：**牧场整个架构是未来数字教会的雏形**——不以教会建筑围墙、某位牧者的个人影响范围或国界限制普世肢体的联结，并希望让生命见证跨越世代与时间被后来的人发现。**基督为元首，众肢体共同成为活的基督身体。**

设计中必须同时守住：
1. **基督是元首**：数字空间、步道事工、算法、商业服务或开发者都不是属灵身份的授予者。
2. **服事普世教会而非占有信徒**：不把地方教会、组织、国界、牧者的边界自动变成联结的垄断权；但开放性不意味着取消真实牧养、团契、教会秩序、圣礼与问责。平台不自行宣称取代所有实体教会实践。
3. **圣经、个人领受、技术服务三者分层**：
   - 圣经是神的话语：经文不是产品，但数字译本的版权与 API 授权必须尊重。
   - 个人领受是用户的私密回应：不是可以交易、出售或默认公开的属灵商品，不能与圣经权威混同。
   - 数字空间、原声存储、同步、备份与长期服务是真实技术劳动：将来才可能探索自愿订阅。
4. **步道永久免费，事工属性永不改变**；订阅绝不能购买属灵特权或牧养优先权，若未来产生可支配盈余，要在合法经营主体、教会监督与神学论证之下支持事工。宗教奉献与商业订阅账户、账目和法律性质必须分开。
5. **收费很远，现阶段不做支付**。将来须进行独立教会论、神学伦理、隐私、版权、财务与司法辖区合规审议。
6. **像素美学面向下一代、甚至更下一代**：不是怀旧玩具或廉价游戏化，而是让后代愿意进入数字牧场发现跨世代见证。允许探索、诗意和亲近，但不使用属灵评分、排行榜、粉丝竞争、付费圣洁等级或打卡焦虑。

已形成正式且详细的设计基线：
- `docs/pasture-foundation-charter.md`
- `docs/my-grass/product-archive-v0.3.md`

主旨：「步道是免费的同行；牧草是私人的领受；空间是可信赖的服务。」

## 4. 「我的牧草」产品语义及已经批准的视觉

- 三段式：**读经／领受（默想）／牧养（私人分享与七光关系）**。不要擅自增加独立的“成言”阶段，也不要把它改造成普通社交 feed。
- 一次真实读经由**用户本人原声 + 实际选取的经节出处 + 逐节时间轨迹**构成。左页圣经阅读、右页复古磁带录音工作站、个人古卷必须联动。
- 阅读某章不等于完成读经；点第一节开启本人的连续原声录音，点下一节推进记录；暂停、继续读、结束后可回听；已确认的右页录音机/古卷 V0.4 样式须守住。
- 读经原声不是 AI 合成声音；语音训练、公开发布、合成授权默认为否。
- 私人文字领受和“一粒牧草”微分享不自动公开；只有用户主动选择才可能共享，社交平台开发暂缓。

## 5. 用户提出并经多轮修复的录音问题——最高优先级的真实体验

### 5.1 第一次发现：录错后没有可用的「重新录音」

真实用户完成朗读、回听后发现读错，需要 **「重新录音」** 按钮。
- 新按钮安放在批准的复古录音机上，避免另建与古卷割裂的界面。
- 旧版本有遗留重录函数，但与后来的 **Reading Journey 逐节连续录音**不兼容；最早竟会先删旧音频，后来改为“新录音与时间线及古卷都存成，才替换旧音频”。
- 已形成正式领受 `insightRecord` 或关联微分享/七光的内容不能轻率改写来源；应新开一页另记新的见证。

### 5.2 第二次发现：第二遍／第三遍读错，无法继续反复重录

- 录音中、暂停时提供 **「这遍重来」**：放弃当前不满意的 take，回到可选第一节／新起始节，支持无限次尝试。
- 因为 `MediaRecorder.onstop` 可能延迟，系统使用 **`journeyAttemptToken`** 避免弃用的 take 在下次录音期间突袭写入资料。
- 取消麦克风授权、浏览器异步延迟、归档失败、账号切换等，不得污染原始记录。
- 「保留原声」允许在重新录音准备阶段取消，恢复既有录音及时间线。

### 5.3 第三次发现：强迫重录必须达到第一次录音的终止经节

这是**已经确认不合理、已经修订**的旧规则。旧版试图以强制“同章、同起止节、同译本”防止新旧时间轨迹错配，却错误地把数据库需要强加给人的读经。

**现行设计原则：`系统忠实记录这一次用户真正读过的经节，而不要求这一次重复上一次的范围。`**

因此：
- 重录时**同一书卷、同一章、同一译本**内可以选择不同起始节，也可在本次实际读到的任何节结束。可以比第一次**短，也可以更长**。
- 若本次选取的经文范围与旧记录不同，**保存前须有明确确认**；不确认时仍可继续读或放弃当前 take。
- 只在**新原声 + 新经节时间线 + 新正文/引用 + 古卷归档**全部一致且保存成功后更新当前正式档案；旧音频随后才可退役。
- 在实际浏览器里还必须验收：左页经文正文、经节 ID、起止范围、右页音频、古卷引用、播放跟随是否完全匹配；自动化检查不代表用户已经验收。
- **跨章节连续读经尚非当前方案支持的录音单位**；切换到另一章/译本需要新开一页，暂不把改动范围扩大到跨章重录。

### 5.4 真实用户场景必须反复测试

1. 读 1–10 节 → 完成 → 回听 → 重录只读 1–6 节 → 确认变化 → 回听 → 古卷显示 1–6 节及相应文字；
2. 已读 1–10 节 → 重录从 3 节开始、读到 8 节 → 记录 3–8 节；
3. 第二遍读错 → 「这遍重来」→ 第三遍读错 → 再重来 → 第四遍成功；
4. 暂停 → 选择结束 → 若范围不同可确认更新，不再强迫补全上次范围；
5. 点击确认前取消 → 继续当前 take 或放弃，旧原声仍可回听；
6. 麦克风授权拒绝、停止事件延迟、超过容量、录音生成失败、档案写入失败 → 旧记录不受影响；
7. 已形成领受／已关联微分享／七光来源 → 明确拒绝直接覆盖，建议新开一页；
8. 刷新页面、退出再登录、移动设备屏幕、Safari/Chrome 音频类型、长录音时长、浏览器切换 → 如当前做不到，明确标记未完成，不能冒称跨设备可靠存储。

## 6. 当前最值得警惕的技术债与现实限制

- 「我的牧草」距可靠的**云端存储、备份、加密、同步、恢复、删除和跨设备恢复**仍有距离；这是完整闭环的前提，之后才应考虑社交。
- **原声本地音频**可能因浏览器/站点存储丢失。现有导出是人工备份，不是服务器上的容灾。
- 已发布的首卡、居民身份、羊和旧档案不能因为新测试或重构被重置。
- Preview 与 Production 是否共用 `DATABASE_URL` 需严谨复核，不要让 Preview 测试污染真实正式库。
- 每次新的 UI、脚本改造都可能打断古卷页、经文读者 iframe 桥接、读经录音暂停按钮或七光关联；必须保留测试和浏览器验收。
- `main` 正式站点与工作站 Preview 的发布节奏不同；不要在没有用户明确授权的情况下修改正式环境。
- 未审议的未来商业订阅不得在此阶段引入，也不得使经文与个人灵修领受在法律/功能上混同。

## 7. 新对话建议的工作方式与下一阶段任务

**首先**：确认唯一真实居民可以完整完成**选章—点击经节—原声录制—逐节推进—结束—回听—任意范围反复重录—确认归档—再次回听—领受—七光—日后翻回古卷**。

**其次**：按用户一次反馈完成一次可回滚小改动，不引入无关的社交模块或视觉重构。修改后跑 `npm run build` 及相关录音、古卷、门禁测试，部署 Preview 后公布准确 Vercel Ready 状态与测试数。区分“CI 通过”与“真实浏览器已证实”。

**再次**：有了稳定可用的工作站后，设计可靠的跨设备私人音频和经文档案持久化、备份与恢复；把身份、敏感信息、访问授权、加密、撤回及个人数据控制权纳入数据架构。
