# 同路原野 · 数字牧场底层设计宪章

> **设计原点**：步道是免费的同行；牧草是私人的领受；数字空间是可信赖的服务。
>
> **终极指向**：不建立一个拥有信徒的平台，而建立一处服事基督身体的数字空间。基督是元首，圣经是根基，人不是平台的资产。
>
> **视觉使命**：像素风不是怀旧装饰，而是面向下一代、甚至更下一代的表达语言；让跨世代的生命见证在未来仍有被发现、阅读和回应的可能。

**状态**：创始人确认的产品与事工设计基线；涉及教会论、收费、版权、牧养责任、数据治理的正式制度，仍须接受教会、神学、法律与财务独立审议。

**适用**：budao.org 数字牧场、步道卡、「我的牧草」、后续肢体联结与商业支持服务的产品设计及工程决策。本文不是对任何现实地方教会、牧者或宗派的否定，也不宣称代表整个教会的教义结论。

## 一、神学根基：一位元首，一个身体，众多肢体

1. **基督为元首**：平台、算法、步道事工和开发团队都不是属灵生命的主人。参照《以弗所书》1:22–23、4:11–16。
2. **普世而非封闭**：愿意服事各国、各族、各民、各方的人，不以国界、语言、宗派、单个牧者的影响范围设置不必要的人为围墙。参照《启示录》7:9。
3. **肢体彼此成全**：技术的目标是帮助关系、恩赐与见证自由而负责任地相遇，并非追逐粉丝、点击和用户占有率。参照《哥林多前书》12章。
4. **取消人为垄断，不取消牧养责任**：跨地域、跨教会背景的开放性，不等于取消地方教会的聚集、牧养、监督、圣礼实践及彼此问责。平台不能自行宣称替代实体教会的全部生活。参照《彼得前书》5:2–3。
5. **跨越时间的见证，不是数字永恒**：真实阅读、本人原声、生命领受与见证可以在妥善保管、取得授权的情况下跨越代际流传；技术不代替救恩，也不把个人资料自动变成公共遗产。

**教会论底线**：未来关于“数字教会”的治理、权柄、牧养、圣礼、归属与纪律，须经不同教会传统背景的严肃神学与教会治理审议；当前产品首先是服务基督身体的数字场域，而不预先声称已经实现教会的一切必要要素。

## 二、三个必须在产品与代码中分开的领域

| 领域 | 属灵/伦理定位 | 产品责任 | 商业边界 |
| --- | --- | --- | --- |
| **圣经经文** | 神的话语；任何平台不拥有其属灵权柄 | 依法提供正确来源、译本标识、上下文与阅读能力 | 不出售神的话语或把基本阅读变成属灵收费门槛；具体译本仍须符合版权与 API 授权 |
| **个人灵修领受** | 人在神的话语面前的个人回应，尊重其私密性与作者主体性；不能等同圣经启示 | 记录文字、原声、经文关联、时间与个人关系脉络 | 不出售、挟持或未经同意利用个人领受；用户决定分享与否 |
| **数字空间与服务** | 为长期可信托付提供的技术劳动 | 存储、加密、同步、备份、恢复、检索、运维、数据导出 | 可在条件成熟后探索合理、自愿的服务订阅，不购买属灵身份或特权 |

**工程落实**：
- 经文来源、译本授权与渲染模块独立于个人记录模块和将来的订阅模块；授权不充分时，不能靠把费用命名为“空间费”绕过授权。
- 个人记录按居民身份隔离、默认私密，保留本人声音和资料的知情选择；原声不能暗中转用于声纹训练或模型训练。
- 服务订阅只配置明确的服务资源/容量/支持能力，不能改变步道参与、属灵地位、个人领受的所有权或最基本的数据取回权。
- 取消订阅不得成为扣押私人档案的手段；合理的只读、导出、保留与删除政策应在收费前制定。
- 经文与个人领受的数据模型、权限及界面须保持独立，避免读者误以为个人默想具有圣经同等权威。

## 三、为何选择像素风：为下一代，更为更下一代

像素语言并非为了复制电子游戏，也不仅是复古的审美趣味。设计的真正动机是：**让今天所保存的信仰、同行、领受和见证，能够以未来世代愿意接近、理解、探索的数字空间形式被继续遇见。**

像素由有限单位组合成广大世界，适合表现“每个人都是一个不同的肢体，彼此组合却不失个体”的隐喻。但这一隐喻只是设计诠释，**不是新的神学启示，不以视觉象征取代圣经**。

具体设计准则：

1. **面向未来，不困在怀旧**：像素既可令人亲近，也能承载开阔、诗意、成熟而庄重的世界；拒绝将年轻化等同幼稚化。
2. **跨文化、跨年龄可接近**：不假定所有年轻人都熟悉像素艺术；降低文字、文化符号、设备条件造成的进入门槛，保留多语言与不同能力用户的理解路径。
3. **有发现性，但不游戏化属灵成就**：可以探索、行走、照顾羊群、翻阅古卷；不以灵命等级、排行榜、打卡焦虑、付费徽章衡量属灵成长。
4. **人性与手作感**：像素的克制、可辨认节奏与持续生长的景观，服务安静阅读与真实相遇，不追逐炫技动画或让装饰压过经文。
5. **跨代可持续**：素材、组件、颜色、像素比例、布局、文字的可读性需要形成可维护规范；支持手机与桌面、清晰的非视觉语义、减少动态效果选项，以及长期迁移与保存。
6. **以已验收设计为基线**：44只公共羊与居民自己的羊、牧场景观、已确认的步道卡视觉和「我的牧草」V0.4古卷，不因新需求随意推翻。新表现须兼顾完整性与性能。

**代际传承的隐私边界**：未来“跨越时间”功能不得默认公开已故或长期未登录者的祷告、忏悔、原声与灵修；需设计明确授权、指定受托人、撤回、保留与删除等机制。

## 四、免费步道与未来服务支持

- **步道事工始终免费**，且事工属性不因任何可能的订阅收入改变。
- 不以付款决定是否受欢迎、是否被牧养、是否属于基督身体，也不以付费换取更多属灵祝福。
- 「我的牧草」的主要价值是可信赖的个人生命记录空间，不是售卖福音内容、教会资格或私人信仰数据。
- 未来如出现服务收入，先支付实际技术、运营、安全、税费与必要准备金；可支配盈余是否及如何支持事工，须依合法主体、治理与财务制度实施。订阅款、奉献及募捐不得混同处理。
- 正式商业化前须进行独立的神学、教会治理、版权、隐私、财务与所在地合规审议，尤其注意互联网宗教信息服务相关规则及跨境数据处理要求。当前不启动收费。

## 五、唯一真实居民试行期：先深度，后广度

当前产品主线由创始居民一人持续使用来验证，**运营上暂不邀请第二位真实居民**，但架构必须保留多用户身份隔离、权限、退出、恢复与将来扩容能力；不把代码硬编码成某个人的专属系统。

开发先后次序：

1. **完整跑通「我的牧草」**：步道卡真实激活 → 66卷定位及合法经文加载 → 逐节阅读及本人原声 → 领受与七光关系 → 私人古卷及历史重逢 → 再次打开与持续使用。
2. **先保障真实资料**：云端持久化、可靠备份、跨设备恢复、故障恢复、导出与私密权限，以及原声音频长期保存。浏览器本地存储不得冒充跨设备的永久保管。
3. **真实日常使用驱动迭代**：持续使用、反馈、修复、测试、Preview 验收；维护稳定基线，不以功能数量代替使用质量。
4. **社交模块冻结**：只有个人生命记录闭环稳定可靠之后，才开始讨论互相守望、肢体联结和自愿分享；避免先造关注、粉丝与排名系统。
5. **商业化远期评估**：在价值、可靠性、版权、神学伦理、财务和法律审核成熟前，不设计订阅为进入事工或阅读经文的条件。

## 六、工程与治理不变量

任何新需求、PR、页面重构、数据库调整和上线方案应回答：

- 是否尊重基督为元首、服事基督身体，而不是强化平台对人的占有？
- 是否保持圣经、个人领受和可收费服务在文本、权限和数据上的区别？
- 是否维护步道免费、个人内容私密、退出后可取回数据的原则？
- 是否能让下一代乃至未来世代理解和使用，而不牺牲当代不同年龄及能力者的可接近性？
- 是否守住已经通过验收的视觉和功能基线？
- 是否有真实可验证的自动化/浏览器验收、可回滚的部署和明确的居民数据保护？
- 是否把需要牧者、教会和法律共同审议的事项误写为既定教义或已获许可的商业能力？

**发布规则**：设计文档与 Preview 可以持续迭代；生产环境合并与公开服务范围变更，仍须由项目负责人明确授权。已发行的卡、羊、读经原声和个人领受必须受保护。

---

**一句话北极星**：**让下一代、甚至更下一代的人，通过一处自由、可信、可持续的数字牧场，与基督身体中不同时空的真实见证相遇；同时始终承认，基督才是教会的元首，技术只是服事的器皿。**
