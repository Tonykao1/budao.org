# 牧草：匿名领受 → 真实同行 → 身份互认 → 属灵关怀
**RFC V1 · 2026-10-28 · Design constraints / Preview-only foundation**

## 0. 使命，不是社交产品
“数字教会”跨越地理和组织边界，让圣徒在基督身体里互为肢体，成为关怀、扶持、代祷与服事流动的血液和淋巴（比喻）。不替代实体团契的聚集、圣礼/礼仪、教会监督与可信牧者职责；不靠技术决定谁真正属于基督。
圣经核对：使徒行传 2:42–47；约翰福音 13:34–35；哥林多前书 12:12–27；以弗所书 4:15–16；雅各书 1:22。

## 1. 不可更改的产品要求
1. **基督为中心、福音导向**，真实生活及真实基督徒群体为目标，不以灵修打卡、算法评分或增长指标取代门徒塑造。
2. **录音始终是正式领受的必要前提**。可以出声读经，也可以静默录制（默录）。禁止用语音识别、音量阈值、时长打分判定灵性或默读真实性。录音应明确征求设备权限，保留失败重录能力，绝不暗中录制。
3. **不加入 AI 释经/属灵代言人**。圣经解释应由经文上下文、真实教导者和适当的教会牧养责任保障；任何 AI 不得冒充圣灵、牧者或神学权威。
4. **领受可跨地域匿名分享**，但用户默认仍处于私人状态，单次分享必须确认具体公开文本。
5. **只有真实步道联结之后，才有资格申请彼此身份解锁**；同路本身不自动解锁，双方各自明确授权且可拒绝。
6. **可信身份与教会连接透明**：平台层居民凭证、真实同走凭证、教会授权/认领凭证是三个不同的验证层级，不得互相冒名。
7. **步道 + 易彼益**：步道提供真实同行场景，易彼益（易/彼/益）提供奉献、承接和资源流动的行动通路。易彼益交接记录本身不等于灵修身份互认，不将奉献量、步数或益处兑换成属灵地位。
8. 牧草已有一个“领”中心和六个关系方向（传、忆、连、求、行、去）。**新增的是横跨匿名内容与真实关系的“可信同行维度”**，并非再添一个装饰性的第七个光点。

## 2. 从匿名内容到真实身份：权限状态
```
本机领受 PRIVATE_LOCAL
    ↓ 独立选取 <=80 字、显著提示匿名风险、本人明确同意
匿名公开分享 ANONYMOUS_PUBLISHED
    ↓ 只允许对内容回应/请求参与步道，不开放私信、身份、录音与位置
等待真实同行 AWAITING_VERIFIED_COWALK
    ↓ 步道活动已经结束，双方存在组织方确认的可信同行见证
共同经历已验证 VERIFIED_COWALK
    ↓ 两位居民分别针对相互身份和该份领受独立同意
身份互认 MUTUALLY_UNLOCKED
    ↓ 完全自愿，另行征求授权，进入祷告、关怀与易彼益实践
可信同行与服事 FELLOWSHIP / STEWARDSHIP
```
每个阶段都允许停止，不强迫进入下一阶段。取消授权、屏蔽对方或撤回分享后，未来访问立即关闭；但系统不能抹去他人已经记住、保存或截图的身份。

## 3. 两种不同的“身份”
- **平台后台可信居民**：服务器登录会话、居民 ID 与步道卡权限；不能仅靠本地存储卡面、昵称或邮箱来当作身份权威。
- **前台匿名分享者**：每一条分享采用独立随机 ID；匿名阅读界面不得输出居民 ID、邮箱、账户昵称、地理位置、教会归属、音频文件、录制时间精度、历次分享之间的稳定化名、跨站可关联追踪标记。
- **互认后可见身份**：默认仅双方约定的展示名及他们自愿公开的教会连接；电话、邮件、家庭地址、准确地理位置、私人录音、完整原始领受文稿**不因互认自动开放**。
- **教会透明**：用户本人可查看自己绑定的是哪一间真实机构、如何验证、谁对牧养联系负责及撤回流程。旁人只可看见经当事人与机构明确授权的教会关系，不暗示“平台已确认神学正统”。

## 4. 匿名文本必须与私人母本物理分离
- 私人母本：音频、完整两栏领受、默想、关系六光、相关身份，默认只保留在居民自己的存储空间。
- 公开副本：用户主动选出的短文本 + 经文出处 + 随机分享 ID；不得附带音频、私人关系图、姓名、教会、参加路线、精确时间。
- 录音是“正式领受”的硬前提，但**不是匿名分享的媒体**。静默录制与发声录制都符合录音门槛；不得以沉默为虚假数据。
- 自动防泄露检测只能覆盖明显邮箱、手机号、链接等；不能承诺自动判断每一段个人故事都不会反向暴露身份。发布前必须可预览、撤回、举报与屏蔽。
- 分享不得默认推荐附近路线，也不得用实时位置、活动签到、步数或易彼益申请历史推断作者是谁。

## 5. “步道联结”的最低可靠见证
1. 由服务器登记真实步道活动、组织者及参与者；活动必须完成。
2. 两人各自拥有可核实的参与凭证，**组织者事后见证/确认**，禁止仅凭 GPS、同一日步数、二维码截屏、路线浏览或自报“我参加了”。
3. 双方分别在同行后针对这一条匿名分享点击“愿意互认”，服务器验证批准发生在活动完成之后；不能由同工代表某方擅自同意。
4. 任一方撤销、屏蔽、举报或分享撤回，平台立刻阻断后续身份详情请求；所有权限由服务端逐次判断，不将开锁布尔值放在浏览器 localStorage 作为权威。
5. 对疑似骚扰、跟踪、未成年人或高风险个人处境，优先限制身份互认和一对一联系，并提供人工申诉、封禁与教会责任转介机制。
6. 配对完成也**不表示**两人具有牧养关系或实际教会成员资格；双方可以建立陪伴，也有权不继续。

## 6. 与步道、易彼益、牧场的实际关系
```
牧草（经文 → 录制 → 领受）
      │ 自愿仅分享审核过的短文
      ▼
匿名的领受，跨地域可被看见
      │ 对生命的回应 / 实际愿意同行
      ▼
步道活动：申请 → 共同走过 → 组织者验证
      │ 双方再次同意
      ▼
身份互认（仅双方）：允许继续建立信任
      ├── 祷告、探访、属灵关怀、回归实体教会
      └── 易彼益：真实需要与资源奉献，实际步道交接
```
易彼益原有的“易—彼—益”交接流程保持独立。没有自动分配资源、自动对应灵修领受或把积分/益币当作灵性指标的行为。

## 7. 工程现实与先后次序
**目前已有**：牧场居民服务端会话、步道卡激活、牧草本地可信录音母本、领受 ID、六方向私人关系、易彼益独立申请与交接流程。
**目前没有**：可验证的两位居民真实同走凭证、匿名跨地域的内容服务/审核队列、跨系统实名互认服务、经教会核实的关联与牧者响应 SLA，也没有多年私密音频跨设备安全备份。
因此绝不把“匿名分享”“身份解锁”按钮伪装成已联网工作。

### 分期
- **G0（当前）**：冻结上述神学与隐私约束；服务器专用纯策略模块和拒绝路径测试。暂不出现可发布的公开 UI。
- **G1**：真实步道活动登记与事后双向参与验证；投诉和撤回体系；与居民登录关联。
- **G2**：匿名内容服务、逐条明确同意、敏感文本预览、内容风控及跨地域可发现性；音频母本仍私人。
- **G3**：完成同走见证后双向身份互认；有限可见身份与可撤回授权；教会关联的单独认证流程。
- **G4**：自愿祷告、关怀、实际陪伴，和独立的易彼益资源给与/接受。安全试点通过再扩展。

## 8. 验收标准（不可用概念或视觉代替）
- 未录音不能完成正式领受；静默录制可完成，不能因为没有语音而拒绝。
- 无本人确认的分享短文永远不进入公开服务器；默认不公开私人原声。
- 匿名 API 响应不包含可用于恢复身份的私有字段。
- 仅同场活动、只报步数、只完成物品交接、仅一方同意，都无法解锁身份。
- 两位用户都获得经过活动后组织者见证的参与凭证，且对具体互认分别同意，服务端才允许见到双方选定的身份字段。
- 任一方屏蔽或撤回后，下一次身份详情访问拒绝。
- 全流程无 AI 释经、无自动属灵评分、无可出售的信仰画像、无强制教会归属。
- 跨地区可访问，但真实关怀必须有可追责的真人联系与教会转介边界。
