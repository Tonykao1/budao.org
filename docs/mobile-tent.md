# BUDAO · 掌上帐篷（Mobile Tent）

独立手机端入口：部署到主站后，访问 https://budao.org/mobile-tent.html 。可将此 URL 直接发到微信，带领人无需电脑即可在微信内置浏览器打开。

## 第一阶段范围
- 沿用现有 Tent 带领人账号与签名 HttpOnly Session，未授权者不能读取私有路线或发布
- 使用响应式手机表单录入已有帐篷线路字段，按原线路 schema 发布
- 地点层级不再由带领人手工输入：国家／地区、省／州／直辖市、城市／区县、路面／地形四项必填；系统只用前三项固定生成「国家 · 省州 · 城市／区县」，地形单独存储。旧线路只在格式完全符合三段时回填。
- 登录后加载属于该带领人的所有线路，可新建或选取已有线路编辑
- 本机自动保存文字草稿，按带领人和线路 ID 隔离；不会保存密码、照片或二维码
- 手机相册选择封面与二维码，经受保护的原有上传 API 存储；二维码保持全图不裁剪
- 发布前核对预览，成功后提供网站入口
- 原始发布 API 保持不变；/api/routes?scope=mine-all 只返回当前已认证账号所有线路
- 更新已有路线优先按已认证的所有者 + 稳定 routeId 匹配，兼容老帐篷按日期/标题匹配的历史写法
- 本阶段不包含微信服务器消息接收、公众号 Bot 或邮件自动解析入库

## 第二阶段：真实线路发布链路（已开发，生产尚未发布）
- 沿用 `POST /api/publish-route-v2` 写入正式线路库；手机端发送 `X-Budao-Mobile-Tent: 1` 触发严格必填、日期、时间、地点层级四重校验，不修改旧版 Tent 的请求格式。
- 所有权由服务端签名会话确认，编辑已有线路需匹配其本人稳定 routeId；不存在、已转移或伪造的 ID 返回 404，不自动新建替代。
- 图片和二维码通过原有 `/api/upload-route-image` 上传，路径绑定带领人；沿用旧图时服从原有图片可信来源规则。
- GitHub 写入成功（commit 或幂等确认）后，手机端回读个人线路及公开日历，分别报告“保存成功”和“公开显示”；不会因为读回失败诱导重复发布。
- 个人线路读取失败返回 503 而非空数组；手机端禁止提交，避免误把故障当作“没有历史线路”。
- 既有线路若被锁定，或移动端不能查询监督状态，服务端拒绝修改。
- 确认写入后清除文字草稿，编辑器继续选中刚刚发布的路线。
- 使用模拟 GitHub API 完成新增、编辑、重复提交、预览拦截、鉴权、图像上传、冲突与监督状态测试；这不等于已在正式站执行实际写入验收。

## 安全 / 部署边界
- 没有增加 Vercel Serverless Function；使用现有 auth、routes、image upload、publish API。
- 新功能在非 main 分支开发。除了手机页面在 *.vercel.app 上禁用按钮，`publish-route-v2`、`upload-route-image`、`routes` 的写入操作也由服务端拒绝 preview/development 环境；生产只允许写向 main。
- 此保护针对上述帐篷线路相关接口，不宣称隔离整个站点的所有其他写入能力。
- 主站采用自定义域名发布后，才允许手机端正常使用“确认发布”。暂不应向普通带领人承诺预览站能实际发布。
- 原系统验证机制仍为服务端 Session + SameSite Cookie + 同源验证，不信任客户端提供的 owner/role/slot。
- 草稿保存在当前手机浏览器本地。同一设备的其他使用者可能看到草稿；共用设备完成后应自行清理网站数据。
- 旧线路如果保存的是 data URL 内嵌二维码，修改前应重新上传二维码，才能满足目前服务端图片白名单。

## 验收清单
1. 未登录访问 mobile-tent.html 显示登录；登录错误正确提示。
2. 已登录带领人加载自己的全部线路，不能读取其他带领人的线路。
3. 新线路填写日期、名称、集合地点、时间、活动性质等字段，返回预览。
4. 从手机相册选择 JPEG / PNG / WebP，上传完成后发布接口接收的是受控图片 URL。
5. 二维码不裁切、不变形；发布前对原始活动二维码实际扫码验证。
6. 修改旧线路的标题和日期，保持 routeId，不创建重复路线。
7. 在微信内置浏览器与 iOS Safari / Android Chrome 测试提交、文字草稿、会话过期。
8. 发布失败（401/409/423/429/图片过大）时保留编辑状态，不误报成功。
9. 预览部署不可发布；合并上线前复核发布分支环境变量与发布写入权限。
10. 全站回归与首页 Slot/日历投影逻辑无变化。

## 回滚
该入口是独立静态文件。回滚时移除新页面入口和静态资源，并回退 mine-all scope 和 routeId 匹配改动；既有帐篷和网站不依赖手机端页面。

## 上线验收条件
1. 在受保护的 PR 上确认 Vercel READY 且所有专项及既有构建测试通过。
2. 在负责人批准生产发布之后合并至 main；Vercel 自动生产部署完成后先验证原 Tent 登录、首页 Slot、日历和资料读取。
3. 使用指定带领人账号在生产端发布**明确标注为测试**的新线路，确认个人库/日历呈现后按正式流程处理测试记录；真实写入验收未完成前不得声称全链路生产验收通过。
4. 后续测试包含用户已验收的手机填写体验、微信内置浏览器中的生产登录和相册/二维码选择。
