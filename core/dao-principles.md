# 道｜底层逻辑

> 本文件保存“道”系统的宪法级原则。产品、数据结构、同道调用、道卡生成与后续研发不得在未明确讨论的情况下偏离这些原则。

## 一、七问底层逻辑

1. **Q1 — OPEN**：任何人都可以进入的开放问题；建立安全、自然的交流入口。
2. **Q2 — EXPERIENCE**：从人的生活经验出发，使交流由表面信息进入个人经验。
3. **Q3 — ENCOUNTER**：建立人与人的真实相遇；仍保持非信仰前置门槛。
4. **Q4 — HEART**：开始直指内心，使问题从外部世界转向“我自己”。
5. **Q5 — SCRIPTURE_THRESHOLD**：抵达经文门口；把人的真实处境带到经文面前，为经文揭示作预备。
6. **Q6 — CONFRONTATION**：思想已经揭示的经文，让经文与老我发生真实冲突、审视、纠正与争战。
7. **Q7 — GOSPEL_RESPONSE**：披挂耶稣基督的救恩，进入新生命，并作出回应；避免把回应退化为靠旧人改善旧人的行为主义。

七问不是七个平行问题，而是一条有方向的属灵路径：

**开放 → 经验 → 相遇 → 内心 → 经文门槛 → 经文对付 → 福音回应**

## 二、道从哪里来

**人的日常圣经生活生产“道”，步道只是让这道进入人与人的同行。**

“道”不是为了某一次活动临时制造的活动素材。带领人日常查经、思想、祷告、挣扎与领受，经过七问结构化以后形成一道；步道、同道、道卡、分享、讲道与音视频，都是这一道后续进入共同体的不同方式。

## 三、查验边界

进入公共“道池”和同道模板之前，必须经过查验。

但必须长期保持警醒：**系统查验者、超级管理员、牧者或任何少数人都不能成为类似“教皇”的终极裁决者。人的查验承担的是秩序、释经责任、结构完整、内容可靠与共同体守望；真正的终极查验者，只能是圣灵。**

因此产品设计应同时坚持：

- 人人可以学习、领受并提交；
- 公开进入道池与同道模板前必须有人承担查验责任；
- 不因身份、宗派、头衔自动授予真理特权；
- 不把人的审核机制包装成终极属灵权威；
- 保留谦卑、可问责与共同辨识的空间。

## 四、发布后冻结

一道在查验通过并正式发布以后，不再修改。任何内容修改都应形成一道新的“道”、新的发布日期与新的道号。这样保证“一道一号，一号一内容”，并保护已经分享、印刷或通过二维码访问的历史内容不被悄然改写。
